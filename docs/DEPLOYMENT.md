An inaccurate server clock will corrupt audit timestamps, document sequencing, invoice dates, scheduled backups, and token expiry.**Run the commands in [CLOCK_VERIFICATION.md](./CLOCK_VERIFICATION.md) before any deploy or first-run, and verify:- Web server UTC clock within ±5 seconds of a trusted NTP reference (e.g. `time.windows.com` or pool.ntp.org).- SQL Server `SYSUTCDATETIME()` matches web server `DateTime.UtcNow` within ±2 seconds.- `w32tm /query /status` reports a valid NTP source **and** `Last Successful Sync Time` within the last 7 days.**Gate rule:** If the clock is stale by >5 minutes OR future-dated by >1 minute, **abort deploy**. Fix NTP first.**Important:** Audit artifacts in this repository dated August 2026 were produced on a sandbox clock during development. Do NOT treat those timestamps as real production dates.---## 9.
