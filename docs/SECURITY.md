Identity Setup### 1.1 Framework & Storage- **Framework**: ASP.NET Core Identity (`Microsoft.AspNetCore.Identity` + EntityFramework stores), backed by the same `LivestockDbContext` as the app schema (tables `AspNet*` live alongside app tables).- **User Entity**: `ApplicationUser : IdentityUser` (extended columns defined in DATABASE.md).- **Role Entity**: `ApplicationRole : IdentityRole` with `Description` + `Rank`.- **Password Hasher**: Default ASP.NET Core Identity v3 PBKDF2 with 100,000 iterations SHA512 (Identity defaults in .NET 8).- **Claims Principal**: On login, cookie contains:  - `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier` → `User.Id`  - `name` → `UserName`  - `email` → `Email` (if confirmed)  - `role` → 1..N role claims (one per assigned role)  - `CompanyId` → `User.CompanyId` (absent for SystemAdministrator)  - `FullName` → `User.FullName`  - `SecurityStamp` — standard  - `amr` → authentication method (`pwd`, `mfa`)- **Cookie Options** (`AddIdentityCookies`):  - Name: `.Livestock.Identity`  - HttpOnly: always  - SecurePolicy: Always in Staging/Production; SameSite=Lax; in Development SameSite=None when local dev uses HTTPS  - ExpireTimeSpan: 12 hours absolute  - SlidingExpiration: true, regenerate after 30 min idle  - SessionStore: distributed cache-backed (prevents oversized cookies if > 4096 bytes)### 1.2 Password Policy```csharpservices.Configure<IdentityOptions>(options =>{    options.Password.RequireDigit = true;    options.Password.RequireLowercase = true;    options.Password.RequireUppercase = true;    options.Password.RequireNonAlphanumeric = true;    options.Password.RequiredLength = 10;    options.Password.RequiredUniqueChars = 6;    options.Lockout.DefaultLockoutTimeSpan = TimeSpan.FromMinutes(5);    options.Lockout.MaxFailedAccessAttempts = 5;    options.Lockout.AllowedForNewUsers = true;    options.User.RequireUniqueEmail = true;    options.SignIn.RequireConfirmedEmail = false; // Optional for self-onboarding only. CSRF (Cross-Site Request Forgery)### 4.1 Global Enforcement- `builder.Services.AddAntiforgery(options => { options.HeaderName = "X-XSRF-TOKEN"; options.Cookie.HttpOnly = true; options.Cookie.SecurePolicy = CookieSecurePolicy.Always; options.Cookie.SameSite = SameSiteMode.Strict; });`- MVC/Razor: `options.Filters.Add<AutoValidateAntiforgeryTokenAuthorizationFilter>();` → auto-validates for all non-idempotent HTTP methods (POST/PUT/PATCH/DELETE).- AJAX calls: page footer emits cookie `XSRF-TOKEN` (JS reads cookie value → places `X-XSRF-TOKEN` header on fetch calls).- API controllers: `[AutoValidateAntiforgeryToken]` on base controller class.- Exception: `/health` (GET, anonymous), Hangfire (uses its own token), identity scaffolded pages already include tokens.### 4.2 SameSite Cookie Matrix| Cookie | SameSite | Secure | HttpOnly ||---|---|---|---|| Identity auth cookie | Lax | Always (prod) | YES || Antiforgery cookie | Strict | Always | NO (intentionally; JS reads for AJAX) || Session | Lax | Always | YES || Hangfire cookie | Strict | Always | YES |---## 5. XSS (Cross-Site Scripting)### 5.1 Output Encoding Defaults- All Razor views use `@expression` (HTML encode by default) — never `@Html.Raw()` except explicitly whitelisted cases (e.g. rendering Markdown-rendered Notes that have passed `HtmlSanitizer`).- JavaScript reads user content from server via `data-*` attributes or JSON (not innerHTML of untrusted data).### 5.2 Content-Security-Policy (CSP) HeaderMiddleware emits:```Content-Security-Policy:  default-src 'self';  script-src 'self' 'unsafe-inline' 'unsafe-eval' https://cdn.jsdelivr.net;  style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net;  img-src 'self' data: https:;  font-src 'self' data:;  connect-src 'self';  frame-ancestors 'none';  base-uri 'self';  form-action 'self';  object-src 'none';  block-all-mixed-content;  upgrade-insecure-requests;  report-uri /csp-report-endpoint;```(report-only mode first in pre-prod for 2 weeks before enforcing).### 5.3 Input Validation- All string fields subject to max length, Regex validators for phone, email, zip; rich text: none allowed (plain text Notes only; no HTML/Markdown in v1, so CSP is extra defense.---## 6. File Upload — Allow-List & Hardening### 6.1 Allow-List Extensions & Limits| Category | Allowed Extensions | Max Size Per File ||---|---|---|| **Global (applied to all upload endpoints | `.pdf` `.jpg` `.jpeg` `.png` `.doc` `.docx` `.xls` `.xlsx` `.csv` | **10 MB (10,485,760 bytes) |NOT allowed: `.exe`, `.bat`, `.js`, `.html`, `.htm`, `.svg`, `.zip`, `.rar`, `.7z`, `.msi`, `.ps1`, any extension not in the list (case-insensitive extension check).### 6.2 Validation Layers1. **Client-side JS (defense-in-depth only — reject bad extension & oversized.2. **Server-side by `FileUploadValidator`:   a. Strip path traversal protection — filename contains `..` → reject.   b. `Path.GetExtension(fileName.ToLowerInvariant()` against fixed allow-list (ord/ordinal).   c. `file.Length <= 10*1024*1024`.   d. **Magic-byte signature verification (InputStream rewind and check header bytes):      ```      JPEG: FF D8 FF      PNG : 89 50 4E 47 0D 0A 1A 0A      PDF : 25 50 44 46 (%PDF)      DOCX/XLSX: 50 4B 03 04 (ZIP) + extension match      CSV: extension + content check (no binary NUL bytes in first 4096)      ```   e. MIME type vs extension cross-check: e.g. `.pdf` claims `application/pdf`.   f. Save using GUID as target filename (never original filename).   g. Compute SHA-256 hash → dedupe.3. **Storage**: files never stored under web root (wwwroot). Deliver via `/files/{id}` endpoint that validates permission + sets `Content-Disposition: attachment` + correct MIME. Never `inline` (prevents MIME sniff based XSS on PDF/image polyglots).4. **Response headers on file download**: `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`, `X-Frame-Options: DENY`.### 6.3 QuotaPer-company 50 GB default quota. Uploads blocked when `SUM(SizeBytes) > Company.StorageQuotaGb * 1024^3`.---## 7. Company Isolation — `CompanyId` Global Query Filter### 7.1 Enforcement LayersThree independent defenses so a single bug cannot leak data:1. **EF Core Global Query Filter** — `modelBuilder.Entity<T>().HasQueryFilter(e => e.CompanyId == _currentCompanyId.Value)` — applied automatically on any LINQ query.2. **`SaveChangesAsync` override** — on INSERT/UPDATE: if entity `IHaveCompanyId.CompanyId != CurrentUser.CompanyId` → throw `CrossCompanyWriteException` (unless SystemAdministrator and explicitly impersonating).3. **Authorization policy** on every page/action: user must be in the target company OR SystemAdministrator.### 7.2 SystemAdministrator Impersonation- Top-right company-picker dropdown appears only for `SystemAdministrator`.- On company switch → new `CompanyId` saved to Session + `AspNetUserClaims` (transient claim type `ImpersonatingCompanyId`).- Every DB query uses `_companyContext.CompanyId` = `Session value OR user's own CompanyId claim`.- Every audit log during impersonation carries `Impersonating=true`, `OriginalUserId`, `TargetCompanyId` → immutable audit fields; actions are fully attributed.- Drop "Exit impersonation" reverts to cross-company view.---## 8.
