Anonymous user hits login page (AllowAnonymous).2. `SignInManager.PasswordSignInAsync(use2fa = true)`; if MFA enrolled challenges TOTP.3. On success, a `ClaimsIdentity` is created with claims:   - `ClaimTypes.NameIdentifier` = `AspNetUsers.Id`   - `ClaimTypes.Name` = `UserName`   - `ClaimTypes.Email` = `Email`   - `ClaimTypes.Role` (one or more)   - `CompanyIdClaimType = "CompanyId"` = `ApplicationUser.CompanyId` (missing for SysAdmins)   - `FullNameClaimType = "FullName"`4. `CompanyContextEnrichmentMiddleware` reads the `CompanyId` claim on every authenticated request and populates the scoped `ICompanyContext`. If a SystemAdministrator is "impersonating" a company via a dropdown choice, the selected company id is stored in `Session` and overrides the claim (audit logged).### Authorization policiesSee `SECURITY.md` for the full role-to-policy matrix. Policies are defined in Web DI:```csharpservices.AddAuthorization(options =>{    options.AddPolicy("CanViewCompanies",            p => p.RequireRole(SystemAdmin, CompanyAdmin));    options.AddPolicy("CanManageCompanies",          p => p.RequireRole(SystemAdmin));    options.AddPolicy("CanViewLivestock",            p => p.RequireRole(AllAuthenticated));    options.AddPolicy("CanManageLivestock",          p => p.RequireRole(FarmManager, DataEntry, CompanyAdmin));    // ... each module gets View / Create / Edit / Delete granular policies    options.AddPolicy("CanExportReports",            p => p.RequireRole(DataEntry, FarmManager, Accounts, CompanyAdmin, SystemAdmin));    options.AddPolicy("CanVoidInvoices",             p => p.RequireRole(Accounts, CompanyAdmin, SystemAdmin));});```---## 5. EF Core Persistence### `LivestockDbContext` (Infrastructure project)- One DbContext aggregates both the app schema and Identity schema.- Override `OnModelCreating(ModelBuilder)`:  - Apply all `IEntityTypeConfiguration<>` classes via `modelBuilder.ApplyConfigurationsFromAssembly(typeof(LivestockDbContext).Assembly)`  - Define global query filters:    - `Entity<SoftDeletableEntity>().HasQueryFilter(e => !e.IsDeleted)`    - `Entity<IHaveCompanyId>().HasQueryFilter(e => e.CompanyId == EF.Property<Guid?>(this, "CurrentCompanyId"))` — set via `SetCompanyIdFilter(Guid?)` called by the unit-of-work begin.  - Map enums as strings (or short 2-char codes for livestock types):    - `LivestockType -> char(2), fixed-length`    - `DocumentStatus -> nvarchar(32)`    - `PaymentMethod -> nvarchar(32)`- Override `SaveChangesAsync(CancellationToken)`:  1. Enumerate ChangeTracker entries; populate `CreatedAt = DateTimeOffset.UtcNow` / `ModifiedAt = ...` for `IAuditableEntity`.  2. Intercept soft-deletes (set `IsDeleted = true`, `ModifiedAt` instead of actually deleting).  3. Company isolation guard: if the current user context has a CompanyId set, verify every Added/Modified `IHaveCompanyId` entity matches.  4. Collect before/after property values; enqueue an audit-log entry for `AuditedEntity` entries (written inside the same transaction).  5. Save; return count.### Concurrency- Every auditable row has `Version byte[]` mapped to SQL Server `rowversion` (auto-incremented by DB on change).- `DbUpdateConcurrencyException` caught in a pipeline behavior; translates to a typed `ConcurrencyConflictException` with human-readable message, surfaced to UI as a toast + reload prompt.### Repository pattern- Generic `IRepository<TEntity>` with: `GetByIdAsync`, `ListAsync(spec)`, `CountAsync(spec)`, `AddAsync`, `Update`, `Delete` (soft).- Specification pattern (`Ardalis.Specification` package) encapsulates reusable queries with includes, filters, ordering, pagination.- Read-heavy report queries bypass repositories and use direct `DbContext.Set<T>().FromSqlInterpolated()` or Dapper (via `IReportConnection` abstraction) for raw SQL performance, still subject to the Company filter.---## 6. File Storage Strategy### Abstraction (Application)```public interface IFileStorage{    Task<string> SaveFileAsync(Stream content, string logicalFolder, string fileName,                                string contentType, CancellationToken ct);    Task<Stream> GetFileAsync(string storageKey, CancellationToken ct);    Task DeleteFileAsync(string storageKey, CancellationToken ct);    Task<bool> ExistsAsync(string storageKey, CancellationToken ct);    long MaxFileSizeBytes { get; }       // 10 * 1024 * 1024 = 10,485,760    IReadOnlySet<string> AllowedExtensions { get; } // { ".pdf", ".jpg", ... }}```### Implementations- **LocalDiskFileStorage** (dev, on-prem, SMB share):  - Root path `FileStorage:LocalPath` (e.g. `D:\LivestockData\Files`).  - Files stored as `{root}/{companyId}/{logicalFolder}/{yyyy-MM}/{guid128.ext}`.  - Folder ACL: AppPool Identity = Modify; Administrators = Full.  - StoredFile table row: `Id, CompanyId, LogicalKey (storageKey), OriginalFileName, SizeBytes, MimeType, HashSHA256, CreatedById, CreatedAt`.- **AzureBlobFileStorage** (cloud):  - Container `{FileStorage:Container}` in account `{FileStorage:AzureAccount}` using Managed Identity or SAS key from KeyVault.  - Blob path = `{companyId}/{logicalFolder}/{yyyy-MM}/{guid128.ext}`; original filename stored in metadata.  - Soft-delete + versioning + immutable WORM policy enabled for audit records (invoices/financial docs).### Validation enforcement (double layer)1. **Client UI JS**: check extension + size before upload; flash error.2. **Server upload endpoint**:   - Enforce extension allow-list by comparing `Path.GetExtension(file.FileName).ToLowerInvariant()` against `AllowedExtensions`.   - Check `file.Length <= MaxFileSizeBytes`.   - Read first N bytes to validate magic bytes for images (JPEG: `FF D8 FF`, PNG: `89 50 4E 47`, PDF: `25 50 44 46`). Office documents use ZIP signature (`50 4B 03 04`) + extension match check (since they're ZIP-based).   - Never trust `ContentType` alone.   - Compute SHA-256; if duplicate file for same company exists, reuse blob (dedupe).---## 7. PDF Generation Abstraction### Abstraction (Application)```public interface IPdfGenerator{    Task<byte[]> GenerateInvoicePdfAsync(InvoicePdfModel model, CancellationToken ct);    Task<byte[]> GenerateReceiptPdfAsync(ReceiptPdfModel model, CancellationToken ct);    Task<byte[]> GeneratePurchasePdfAsync(PurchasePdfModel model, CancellationToken ct);    Task<byte[]> GenerateLivestockTagSheetAsync(LivestockTagSheetPdfModel model, CancellationToken ct);}```### Implementation: `QuestPdfGenerator` (Infrastructure)- Uses **QuestPDF** (MIT-licensed, NuGet: `QuestPDF`). Fonts: DejaVu Sans shipped as embedded resources for non-Latin glyph fallback.- Output rendered as `byte[]` (stored in `StoredFiles` if "archive invoice PDF" option is on, or streamed directly to response for one-off downloads).- Templates use shared `LetterheadDescriptor` that pulls `Company.Logo`, address, bank details from DB; letterhead is reused for all document types.- Page size: A4 (default) or Letter (company setting `Company.PaperSize`).- Every generated PDF includes: DocumentNumber, PDF timestamp, generator version string in metadata, and a digital "fingerprint" QR code linking to `/api/documents/verify/{hash}` for tamper verification (hash of canonical PDF content bytes stored in StoredFile.HashSHA256).### Background PDF generationWhen a user triggers "email invoice", the controller enqueues via `IEmailQueue.EnqueueInvoiceEmail(invoiceId)`. Hangfire job:1. Load invoice aggregate.2. Call `IPdfGenerator.GenerateInvoicePdfAsync`.3. Persist PDF bytes to StoredFiles (if not yet archived).4. Call `IEmailSender.SendWithAttachmentAsync(to, subject, body, attachment)`.5. Update invoice `LastSentAt`, `SentCount += 1`, `LastSendStatus`.6. On transient failure, Hangfire auto-retries with exponential backoff (1, 2, 4 min, max 3 attempts); final failure moves to dead-letter queue + email alert to accounts team.---## 8. Cross-Cutting Concerns (Behaviors)MediatR open-generic behaviors added via `services.AddTransient(typeof(IPipelineBehavior<,>), typeof(TBehavior<,>))`:| Order | Behavior | Purpose ||---|---|---|| 1 | `RequestLoggingBehavior` | Serilog `BeginScope` with RequestName, UserId, CompanyId; log elapsed milliseconds; warnings for >1s queries. || 2 | `ValidationBehavior` | Runs FluentValidation validators (aggregate failures into `ValidationException`). Throws before business logic. || 3 | `PerformanceLoggingBehavior` | Optional: logs SQL count, memory delta for diagnostics on heavy reports. || 4 | `AuthorizationBehavior` | Re-checks policy-based requirements when a Command carries `[RequiresPolicy]` attribute (defense-in-depth). || 5 | `UnitOfWorkBehavior` | Wraps handler in `_unitOfWork.BeginTransactionAsync(IsolationLevel.ReadCommitted)`. On no exceptions → commit; on Validation/Domain exception → rollback + log. || 6 | `ConcurrencyRetryBehavior` | On `DbUpdateConcurrencyException`, retries the handler once after reloading aggregates (configurable per-request opt-out). |Pipeline order matters: transaction is innermost (wraps handler only), validation happens outside so failures never open transactions.---## 10.
